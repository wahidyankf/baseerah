# Fail-on-Skip Guard Proof — All Three Repos

Phase 2 Gate evidence: for every test tier, in every one of the three repos, a planted skip/disable/ignore
marker was inserted into a real test file, the tier's exact Nx-target command was run, the guard's failure
was captured, and the plant was immediately reverted (verified via `git status --short` showing zero
residue). **14 of the 16 rows below produced a genuine confirmed-red-then-clean-revert proof driven by the
tier's own wired guard command.** **1 row (coralpolyp-fe-e2e, ose-infra)** could not be driven through a
full live end-to-end run (its Playwright suite requires a shared database reset per scenario and has no
`webServer` auto-start), so the guard's own JSON-reporter-parsing logic (the exact `node -e` script from
`project.json`) was instead verified in isolation against a synthetic `results.json` stub — a genuine
functional proof of the guard code path, short of a full live run. **1 row (crud-fe-e2e, ose-primer) is a
confirmed real gap**: no fail-on-skip guard of any kind (grep or reporter-based) is wired into its
`test:e2e` target today — this is flagged prominently below, not papered over, and additionally surfaced a
second, unrelated pre-existing failure in that project's `bddgen` step (see the row's notes). Both
exceptions are called out explicitly in their own rows and in the notes section at the end.

## Notes on the two exceptions

### Row 5 — coralpolyp-fe-e2e (isolated verification, not a full live run)

`coralpolyp-fe-e2e`'s Playwright config (`apps/coralpolyp-fe-e2e/playwright.config.ts`) resets a shared
database before every scenario (per an in-file comment) and declares no `webServer` block, so a full live
`test:e2e` run needs a hand-started backend + frontend + database in a consistent state — not achievable
quickly. Instead of skipping this row, the guard's own novel logic — the `node -e` script in
`project.json` that reads `test-results/results.json` and fails on `stats.skipped > 0` — was exercised
directly against a synthetic stub reproducing exactly the shape a real skipped-test run would produce. This
proves the guard code itself is correct; it does not prove the full pipeline (bddgen → playwright → node
script) wires together end-to-end under a live run. `forbidOnly: !!process.env.CI` was separately confirmed
present in the same config file (read-only check, no plant needed).

### Row 6 — crud-fe-e2e (confirmed gap + a second, unrelated pre-existing failure)

Two separate findings, both real and neither papered over:

1. **No fail-on-skip guard exists** for `crud-fe-e2e`'s `test:e2e` target. Its `project.json` command is
   exactly `npx bddgen && npx playwright test` — no grep pre-check (unlike every grep-based row above) and
   no JSON-reporter post-check (unlike row 5). `forbidOnly: !!process.env.CI` is present in
   `playwright.config.ts`, but that only blocks `.only()` in CI, never `.skip()`/`.fixme()` — it does not
   close this gap. This project's Phase 2 Playwright rollout item appears to be incomplete relative to its
   siblings.
2. **A second, unrelated, pre-existing failure** was discovered while attempting to demonstrate the gap
   live: `npx bddgen` for this project already exits 1 on a clean `main` checkout, with zero plant present
   (`git stash` confirmed this), reporting `Missing step definitions: 5` for
   `specs/.../codegen/dart-codegen-fresh-checkout.feature` — a feature intended for a different app, picked
   up because `crud-fe-e2e`'s `featuresRoot` globs the entire shared `crud-web` Gherkin tree. Because
   `bddgen` never succeeds, no generated spec files exist for this project today, so `test:e2e` cannot
   currently be exercised end-to-end at all, independent of the skip-guard question. This is flagged here
   for whoever picks up `crud-fe-e2e`'s Phase 2/3 work — it will need fixing before a fail-on-skip guard can
   be meaningfully verified live for this project.

No other row deviated from its expected result; all toolchains needed (dotnet, cargo, clojure/Kaocha,
Elixir/mix, Go, Gradle, Maven, Flutter) were present and reachable in every repo's environment.
