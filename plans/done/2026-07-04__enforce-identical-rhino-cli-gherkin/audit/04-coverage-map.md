# Phase 0 Audit — Command ↔ Feature Coverage Map

Maps all 41 leaf commands (`audit/01-command-census.md`) to their covering `.feature`(s), using the
per-scenario pass/skip data in `audit/02-hollow-census.md` plus direct feature-file scenario counts.

## Structural finding (new, beyond tech-docs §1.5's Decision-4 candidate list)

**`gherkin/repo-governance/` houses scenarios for 5 different CLI command groups, not just
`repo-governance`.** Confirmed by feature content + `--help` descriptions:

| Feature file (under `repo-governance/`)                                                     | Actually covers CLI leaf            | Not `repo-governance` |
| ------------------------------------------------------------------------------------------- | ----------------------------------- | --------------------- |
| `repo-governance-frontmatter-audit.feature`                                                 | `md frontmatter-dates validate`     | md group              |
| `repo-governance-readme-index-audit.feature`                                                | `md readme-index validate`          | md group              |
| `repo-governance-emoji-audit.feature`                                                       | `convention emoji validate`         | convention group      |
| `repo-governance-license-audit.feature`                                                     | `convention license validate`       | convention group      |
| `repo-governance-agents-md-size.feature` + `repo-governance-instruction-size*.feature` (×3) | `harness instruction-size validate` | harness group         |

Only `repo-governance-vendor-audit.feature`, `repo-governance-layer-coherence.feature`,
`repo-governance-traceability-audit.feature`, and `repo-governance-audit.feature` itself actually
cover the `repo-governance` group's own leaves. There is also **no `convention/` directory on disk
at all** — every scenario for the `convention` command group lives under `repo-governance/` instead.
This means the Phase 1 §1·0 rename step cannot simply rename `repo-governance/` — it must be
**split** across `repo-governance/`, `md/`, `convention/` (new dir), and `harness/` (or an
`instruction-size/`-named home). Flagging this now so Phase 1 planning accounts for it.

## Directories with scenarios not mapped to any of the 41 leaves

- `test-coverage/test-coverage-diff.feature` and `test-coverage-merge.feature` — internal
  `application/testcoverage/{diff,merge}.rs` behavior, not a CLI verb (per tech-docs §1.5/§4). Still
  unbound/hollow; Phase 1's `test-coverage` wiring must cover all 3 files even though only
  `validate` is a CLI-facing leaf.
- `ddd/ddd-bc.feature`, `ddd/ddd-ul.feature` — bounded-context/glossary validation; no corresponding
  top-level CLI group exists yet (unbound).
- `git/git-pre-commit.feature` — git-hook-level behavior (calls into rhino-cli commands from a shell
  hook), not itself a `rhino-cli <verb>` (unbound).
