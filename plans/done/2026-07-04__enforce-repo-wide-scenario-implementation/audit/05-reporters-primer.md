# Test-Tool Reporter & Fail-on-Skip Capability Matrix (Phase 0 Audit — Deliverable 5)

Scope: every test tool unique to ose-primer beyond what ose-public already covers. Verified by running
the tool's own `--help` (or task-help) in the actual installed project directory, plus targeted doc
lookups for anything `--help` didn't settle. `cucumber-js` (crud-be-ts-effect) is included too, even
though it's TS, because deliverable 3 surfaced a live, verified gap in it.

## Cross-cutting takeaway for the plan

Of the 8 ecosystems audited, only **Go (`-json`), JUnit5-via-Maven (JUnit XML, already producing real
artifacts), pytest (`--junit-xml` / `--cucumberjson`), and Dart/Flutter (`--reporter json`)** have a
ready, currently-usable machine-readable report. **Kaocha and ExUnit have no report wired up today** (both
would need a dependency added). **Kotlin/Gradle has deliberately turned its report off** to work around a
Gradle bug — this is a real, non-obvious landmine the plan must design around, not assume away. **Cargo
is stable-channel-blocked** from its own native JSON/JUnit formats. In every single ecosystem checked, the
"skip/pending fails the run" half of the requirement has **no built-in flag** — Dart/Flutter's
`--run-skipped` is the closest thing to one (it forces real execution rather than merely flagging skip
presence), and pytest has a ready-made third-party plugin (`pytest-error-for-skips`) that does exactly
this. Everywhere else, a custom grep-based or report-parsing guard (mirroring what rhino-cli's own
`internal/speccoverage` scanner already does structurally) is the only viable mechanism — which is
consistent with why this plan's runtime-cross-check pattern is being generalized in the first place.
